# Core Rules

This is the single source of truth for all vault logic.
All other files reference these rules. They are not repeated elsewhere.

---

## Purpose of this vault

- Store market conditions in a structured way
- Compare current setups with old setups and patterns
- Record outcomes and improve analysis over time
- Build a growing knowledge base, not a one-time chat

---

## Main analysis rule

Do not analyze a new setup alone if historical files exist.

For every new setup:
1. Read the new setup carefully
2. Search for similar old setups
3. Search for matching pattern files
4. Compare similarities and differences
5. Check past outcomes if available
6. Then give the final market read

If no similar setup exists, say so clearly.

---

## Language rules

Always use probability-based language.

### Preferred wording
- suggests
- supports
- increases probability
- may lead to
- may sweep first
- remains valid if
- weakens if
- invalidated if
- conditionally bullish / bearish
- structurally similar
- needs confirmation

### Never use
- confirms with certainty
- guarantees
- definitely
- 100% sure
- will absolutely happen
- automatic long / short

---

## Signal interpretation rules

- Do not give absolute predictions
- Separate continuation factors from risk factors
- Mention both bullish and bearish elements if both exist
- If opposite-side liquidity is large, mention sweep risk
- Separate short-term path from medium-term path when needed

### Special rule: TRL and OI
When TRL is very low and OI is very high:
- say this may suggest low retail long participation and short-side pressure
- say this may support continuation if the broader trend is bullish
- do not treat it as a fully confirmed long by itself
- always check whether liquidity, structure, reclaim behavior, funding, CVD, or support defense confirm the idea

---

## Pattern match rules

Do not force a pattern match if required signals are missing.

Distinguish between:
- **True pattern match** — all required conditions present, confirmed by outcomes
- **Partial match** — some conditions present, use cautiously
- **Related idea** — similar theme but missing key ingredients
- **Not a match** — reject clearly

A pattern should only be created after at least **3 setups confirm the same behavior**.

## Output format for analysis

1. Market Read
2. Directional Bias (short-term / medium-term)
3. Confidence (Low / Medium / High)
4. Continuation Factors
5. Risk Factors
6. Historical Similarity
7. Most Likely Path
8. Invalidation
9. Final Summary

---

## Definitions

- `setup` = one specific market situation at one point in time
- `pattern` = repeated market behavior confirmed across multiple setups

---

## File update rules

### When to update the same file
- adding AI analysis
- adding outcome
- adding lesson
- adding tags or links

### When to create a new file
- market condition changes significantly
- the setup idea or bias changes meaningfully
- the setup is no longer the same case

Simple rule: same idea = same file. New idea = new file.

---

## Reliability note

A setup with a filled outcome is more reliable than one without.
Always distinguish between structural similarity and actual historical success.
If outcomes are missing, say so clearly in the analysis.
